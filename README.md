# หารบิล 🧾

เว็บแอปสแกนใบเสร็จร้านอาหารแล้วหารค่าใช้จ่ายกับเพื่อน ทำงานในเบราว์เซอร์ทั้งหมด ไม่ต้องมีเซิร์ฟเวอร์เป็นของตัวเอง

## ⚠️ วิธีเปิดไฟล์ให้ถูกต้อง (สำคัญ)

**ห้ามดับเบิลคลิกไฟล์ `index.html` จากข้างในหน้าต่าง ZIP โดยตรง** (เช่นเปิด File Explorer แล้วดับเบิลคลิกเข้าไปดูข้างในไฟล์ `.zip` โดยไม่แตกไฟล์ก่อน) — วิธีนี้ Windows จะแตกไฟล์ `index.html` ออกมาเก็บไว้ที่โฟลเดอร์ชั่วคราวไฟล์เดียว โดยไม่เอาโฟลเดอร์ `css/` และ `js/` ติดมาด้วย ทำให้หน้าเว็บออกมาไม่มีสีสัน/ปุ่มไม่ทำงานเลย (แบบไม่มี style ใด ๆ)

**วิธีที่ถูกต้อง:**
1. คลิกขวาที่ไฟล์ `receipt-splitter.zip` → เลือก **"Extract All..."** (แตกไฟล์ทั้งหมด)
2. เปิดโฟลเดอร์ `receipt-splitter` ที่แตกออกมา
3. ดับเบิลคลิก `index.html` **จากในโฟลเดอร์ที่แตกแล้ว** เท่านั้น

หรือจะข้ามปัญหานี้ไปเลยก็ได้ด้วยการฝากไฟล์ไว้บนเว็บโฮสติ้ง (ดูหัวข้อด้านล่าง) แล้วเปิดผ่านลิงก์ URL ปกติ

## ใช้งานทันที (ไม่ต้องติดตั้งอะไร)

แตกไฟล์ zip แล้วเปิด `index.html` ด้วยเบราว์เซอร์ได้เลย

> หมายเหตุ: ฟีเจอร์สแกนใบเสร็จ (OCR) ต้องต่ออินเทอร์เน็ต (โหลดโมดูลอ่านภาษาจาก CDN) ส่วนการ "เพิ่มลงหน้าจอโฮม" (PWA) ต้องเปิดผ่าน HTTPS เท่านั้น — เปิดจากไฟล์ในเครื่อง (`file://`) จะใช้ฟีเจอร์นี้ไม่ได้ ต้องฝากไฟล์ไว้บนเว็บโฮสติ้งก่อนตามหัวข้อด้านล่าง

## ฝากไฟล์ขึ้นเว็บ (แนะนำ — ทำให้ PWA ใช้งานได้เต็มรูปแบบ)

ไม่ต้องมีเซิร์ฟเวอร์ของตัวเอง เพราะเป็นไฟล์ static ล้วน ๆ ฝากไว้กับ hosting ฟรีได้เลย มี 2 ตัวเลือกหลักที่เหมาะกับโปรเจกต์นี้:

### 🏆 GitHub Pages (แนะนำที่สุดสำหรับโปรเจกต์นี้)

**เหตุผลที่แนะนำ:** ใช้ `git` ที่มีอยู่แล้วในเครื่อง ไม่ต้องติดตั้งเครื่องมือเพิ่ม, ฟรีไม่จำกัด, โค้ดกับที่ฝากอยู่ที่เดียวกัน (repo เดียวกัน push แล้วขึ้นเลย), และรองรับ PWA (HTTPS ให้อัตโนมัติ) ครบ — เหมาะกับเว็บ static ที่ไม่มี backend แบบนี้ที่สุด

รันคำสั่งนี้ใน Git Bash ได้เลย (แทน `pimon-tn` ด้วยชื่อผู้ใช้ GitHub ของตัวเอง ถ้าใช้ username อื่น):

```bash
cd receipt-splitter
git init
git add .
git commit -m "หารบิล: เว็บแอปหารค่าใช้จ่ายจากใบเสร็จ"
git branch -M main
git remote add origin https://github.com/pimon-tn/receipt-splitter.git
git push -u origin main
```

จากนั้นที่หน้า GitHub repo: **Settings → Pages → Source: Deploy from a branch → Branch: `main` / `(root)` → Save**

รอ 1-2 นาที แล้วเข้า `https://pimon-tn.github.io/receipt-splitter/` — เปิดลิงก์นี้บนมือถือแล้วกดเมนูเบราว์เซอร์ → **"เพิ่มลงหน้าจอโฮม"** จะใช้ได้แล้ว (เพราะเป็น HTTPS จริง ไม่ใช่ไฟล์ในเครื่อง)

> ถ้ามีโค้ดอยู่ใน repo นี้แล้ว (เคยรัน `git init` มาก่อน) แค่ `git add . && git commit -m "..." && git push` ได้เลย ไม่ต้องสร้างใหม่

> ถ้า `git push` ขึ้น error แบบ "fetch first" (เพราะ remote มีคอมมิทอยู่ก่อนแล้ว เช่นสร้าง repo พร้อมติ๊ก README ไว้) ให้ `git pull origin main --allow-unrelated-histories` ก่อน แล้ว push ใหม่อีกครั้ง

### 🔥 Firebase Hosting (ตัวเลือกรอง)

เหมาะถ้าอยากได้ CDN ที่เร็วขึ้นอีกนิด หรือต้องการตั้งค่า custom headers/redirects ในอนาคต แต่ต้องติดตั้ง Firebase CLI (Node.js) และสร้างโปรเจกต์ Firebase เพิ่ม ซึ่งมีขั้นตอนมากกว่า GitHub Pages สำหรับเว็บ static ล้วน ๆ แบบนี้:

```bash
npm install -g firebase-tools
firebase login
firebase init hosting   # เลือกโฟลเดอร์นี้เป็น public directory, ตอบ "No" ที่ถามเรื่อง single-page app rewrite
firebase deploy
```

จะได้ลิงก์ประมาณ `https://<ชื่อโปรเจกต์>.web.app`

ทางเลือกอื่นที่ทำได้เหมือนกัน (ลากโฟลเดอร์วางแล้วได้ลิงก์ทันที ไม่ต้องมี CLI): Netlify, Cloudflare Pages

## วิธีใช้งาน

1. **แท็บ "เริ่มต้น"** — เลือกได้ 2 ทาง: **สแกนใบเสร็จ** (ถ่ายรูป/เลือกรูป ให้ระบบอ่านให้) หรือ **กรอกเอง** (กดปุ่ม "เริ่มกรอกรายการเอง" เพื่อข้ามการสแกนไปกรอกรายการด้วยตัวเองได้ทันที ไม่ต้องมีใบเสร็จเลยก็ได้)
2. **แท็บ "รายการ"** — แก้ไขชื่อ/จำนวน/ราคาของแต่ละรายการ เพิ่มลบรายการได้ ตั้งค่าบริการ/VAT ได้
3. **แท็บ "คนกิน"** — เพิ่มรายชื่อคนร่วมบิล และระบุว่าใครกินรายการไหนบ้าง (ถ้าไม่ระบุ ระบบจะหารรายการนั้นให้ทุกคนเท่า ๆ กันโดยอัตโนมัติ)
4. **แท็บ "หารบิล"** — เลือกโหมด "หารเท่ากัน" หรือ "หารตามรายการที่กิน" ระบบจะสรุปยอดที่แต่ละคนต้องจ่าย

ข้อมูลทั้งหมดเก็บไว้ในเบราว์เซอร์ของคุณเท่านั้น (localStorage) กด "เริ่มบิลใหม่" เพื่อล้างข้อมูลได้ทุกเมื่อ

## สำหรับนักพัฒนา

ดู `SKILL.md` สำหรับโครงสร้างโปรเจกต์และแนวทางแก้ไขโค้ด และ `CHANGELOG.md` สำหรับบันทึกการเปลี่ยนแปลง

### รันเทสต์ (unit + integration tests)

โปรเจกต์นี้มีชุดเทสต์อยู่ในโฟลเดอร์ `tests/` ครอบคลุมทั้งการคำนวณ (`splitter.js`), การอ่านใบเสร็จ (`ocr.js`), การบันทึกข้อมูล (`storage.js`) และเทสต์แบบ end-to-end ที่รันแอปตัวจริงบน DOM จำลอง (jsdom) เพื่อจำลองการใช้งานจริงของผู้ใช้ทั้งวงจร (สแกน → เพิ่มรายการ → เพิ่มคน → ตั้งค่า VAT/ค่าบริการ → หารบิล)

การรันเทสต์ต้องมี Node.js (แนะนำเวอร์ชัน 18 ขึ้นไป) — **ไม่จำเป็นสำหรับผู้ใช้ทั่วไปที่แค่เปิดเว็บใช้งาน** มีไว้สำหรับตรวจสอบตอนแก้ไขโค้ดเท่านั้น:

```bash
npm install   # ติดตั้ง jsdom (ใช้เฉพาะตอนรันเทสต์)
npm test      # รันเทสต์ทั้งหมด
```

ผลลัพธ์ที่ควรเห็นถ้าทุกอย่างผ่าน:
```
# tests 35
# suites 10
# pass 35
# fail 0
```
